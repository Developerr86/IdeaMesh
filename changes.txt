I reviewed the Scout stage (the “search agent”) and rebuilt it around a pluggable search layer. Since IdeaMesh is Next.js/TypeScript, not Python, httpx doesn’t apply directly — the equivalent is native fetch with timeouts, retries, and page fetching.

What was wrong before
The Scout stage was locked to Tavily only (src/lib/search/tavily.ts):

Required a paid TAVILY_API_KEY — no free fallback
Raw fetch with no timeouts or retries
Only search snippets (400 chars), no page content
Hardcoded queries, no provider abstraction
What’s new
1. Pluggable search providers (src/lib/search/)
File	Role
types.ts
Shared SearchHit / SearchProvider interface
duckduckgo.ts
Free search via duck-duck-scrape
tavily.ts
Refactored Tavily provider (with timeout)
http.ts
Fetch wrapper + page text extraction (httpx-like)
index.ts
Provider selection, multi-search, enrichment
2. Provider selection (env-driven)
SEARCH_PROVIDER=auto          # default: Tavily if key exists, else DuckDuckGo
TAVILY_API_KEY=               # optional now
SEARCH_ENRICH_PAGES=true      # fetch full page text for top 3 results
auto — Tavily when TAVILY_API_KEY is set, otherwise DuckDuckGo (works without any API key)
duckduckgo — free search only
tavily — Tavily only
Automatic Tavily → DuckDuckGo fallback if the primary provider fails
3. Page fetching (your httpx idea)
For the top 3 results, the agent now fetches the actual page HTML, extracts meta description + body text, and appends it to the LLM prompt. This gives much richer context than snippets alone. Includes SSRF protection (blocks localhost/private IPs).

4. Smarter queries
buildScoutQueries() now also uses brainstorm.coreValueProposition when available from the Mesh stage.

5. More resilient search
Promise.allSettled — one failed query doesn’t kill the whole run
Dedup by URL, sort by relevance score
20s timeout on Tavily, 12s on page fetches with retries
How to use it
Without Tavily (free):

SEARCH_PROVIDER=duckduckgo
# or just leave TAVILY_API_KEY empty with SEARCH_PROVIDER=auto
With Tavily (better quality, paid):

SEARCH_PROVIDER=auto
TAVILY_API_KEY=tvly-...
Scout works out of the box with DuckDuckGo — no search API key required. If you want, we can next wire LLM-generated search queries from brainstorm context, or pass full scout.results into the Compare stage (not just the summary).

What I did to get it running
Fixed corrupted SWC binaries — A clean node_modules reinstall was needed. The native @next/swc-win32-x64-msvc binary was invalid, which caused Turbopack/WASM errors.

Switched dev to Webpack — Turbopack doesn't work on your machine without native SWC. Updated package.json:

"dev": "next dev --webpack"
Added local-dev mode without Supabase — Your .env has no Supabase keys, which crashed proxy.ts and UserMenu. The app now skips auth when Supabase isn't configured and uses localStorage for pipelines (as documented in context.md).

DuckDuckGo rate-limit fix — DDG queries now run sequentially with a 400ms pause instead of all in parallel.
